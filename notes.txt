## AWS
Tools used: 
- **Cloud Formation**: AWS's IAC.  Define resources in a template (we used YAML), which creates them as a **stack**.
	- **Stacks**: groups of resources created and managed as one unit
	- **Change Sets**: preview what will change before you apply it (similar to `terraform plan`)
	- **Rollback**: If deployment fails, Cloud Formation will automatically rollback to the last safe state
- **EC2**: Virtual servers in the cloud
	- **AMI**: OS image the instance boots from
	- **Instance Types**: Sized for different workloads (t3, xl, etc.)
	- **Storage**: EBS is persistent network storage.  Instance storage is temporary and deleted when stack stops
	- **Security**: Uses security groups for network rules, key pairs for SSH, IAM roles for AWS access
- **S3**: Simple Storage Service
	- **Lifecycle Policies**: move or delete objects automatically after a set time.
	- **Versioning**: Keeps old versions of objects, useful for recovery
- **VPC**: Virtual Private Cloud
	- **Isolation**: logically isolate resources in a virtual network with subnets, outside internet access, etc.
- **Secrets Manager**: Stores sensitive values like DB passwords, API keys, tokens, etc.
	- **Encryption**: uses KMS (Key Management Service)
	- **Scheduled Rotation**: Built in scheduling for secrets rotation
	- **Integration** Apps, Lambda, ECS, EKS - nothing is hardcoded
- **Parameter Store**: Stores non-sensitive values
- **CloudWatch**: Monitoring and observability service
	- **Metrics, Logs, Alarms**: Numbers like CPU/network traffic, central log storage, trigger actions when threshold is crossed
- **ECR**: Elastic Container Registry
	- **AWS private Docker/container registry**: build images, tag, push to ECR
	- **Security**: Scans images for known vulnerabilities (CVEs)
	- **Lifecycle Policies**: automatic deletion of old/untagged images to save cost
## Terraform
Infrastructure as Code tool.  Define structure in `.tf` files and Terraform creates and manages it.  Multi-cloud compatible.
- **Language**: HCL (HashiCorp Configuration Language)
- **Declarative**: You describe what you want and Terraform figures out how to build it (Vs. imperative where you define *how* something is done not endstate)
- **Simplicity**: 
	- `init`: sets up the working directory and downloads providers
	- `plan`: previews changes
	- `apply`: makes the changes
	- `destroy`: deletes everything
- **Best Practices**: Store state remotely, keep state files and secrets out of Git, Review the `plan` before running `apply`

## Kubernetes
K8s is software the runs and manages containers across a group of machines.  You tell it what you want (run 3 copies of my app), it self-heals (if a container crashes it restarts/redeploys it), it scales (adds or removes copies depending on load), handles networking and rollouts, managed in AWS in **EKS** (Elastic Kubernetes Service)

I used K9s to manage local cluster development.  Helped me navigate, observe logs, manage deployed applications.

**Control Plane**: The part of K8s that makes decisions for the whole cluster.  It doesn't run apps.  it decides *where* they run and keeps them running.  Acts as the front door with `kubectl` commands.  `etcd` stores cluster settings and current status.  Hosts the scheduler and control manager.

**Node**: Machine (usually a virtual server like EC2) that actually runs the apps.  **Pods** are the unit K8s runs on a node.  It wraps one or more containers (packaged apps).  Kubelet are agents on each node that take instructions from the control plane to ensure pods are running.

- **Architecture**:
	- **Cluster**: A control plane (manager) plus worker nodes (containers)
	- **Control Plane**: brain of the cluster - it runs the API server (`kubectl` commands), `etcd` (cluster settings db), and scheduler
	- **Node**: Worker machine that runs pods (containers)
	- **Namespace**: Logical separation inside a cluster (team or environment)
- **Workloads**:
	- **Pod**: Smallest unit.  One or more containers that share a network
	- **Deployment**: Runs stateless apps.  Handles replicas, rolling updates, and rollbacks
	- **StatefulSet**: For apps that keep data (mainly DBs).  Gives each pod a stable name and storage
- **Networking**:
	- **Service**: Stable address for a group of pods
	- **ClusterIP**:  Reachable only inside the cluster (the default)
	- **LoadBalancer**: Creates a cloud load balancer for outside traffic
	- **Ingress**: Routes HTTP traffic by hostname or path.  Needs an ingress controller to work

## Helm
Package manager for K8s, similar to an app store or `apt` for Linux.  Helm is reusable, simplifies deployments and rollbacks.

Without Helm, you write and apply manage separate K8s YAML files (config files that describe what to run) by hand.
With Helm, those files are bundled into one package that you can install, upgrade, or rollback with a single command.

I migrated our local development object storage from MinIO to SeaweedFS via Helm StatefulSet charts after a licensing change required us to move off MinIO.  I also have a reference letter from a previous supervisor that calls this work out specifically if needed.

**Core Concepts**:
- **Chart**: A Helm package: a folder of K8s YAML templates for an app
- **Template**: A YAML file with placeholders, like `{{ .Values.replicas }}`, that gets filled in at install time
- **`values.yaml`**: The file that fills in those placeholders, such as image version or replica count.
- `chart.yaml`: The chart's info - name, version, description, etc.
